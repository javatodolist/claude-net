# Claude Opus 4.6 刚发布就用 Claude Code 写项目，有哪些要注意的吗？

第一肯定是价格了。
Opus 4.6的官方价格看起来很清楚：输入5美元/百万Token，输出25美元/百万Token。
听起来还行？
但这只是表面。一旦你的输入Token超过200K，整个Request的价格就会翻页。
输入变成10美元/百万Token，输出变成37.5美元/百万Token。这不是超过部分按新价算，而是整个请求都按高价计费。
Anthropic那个demo里，16个Claude实例运行了十多天，消耗了20亿输入Token。最终一算账就是2万美元
思考力度的隐形成本
Opus 4.6有个"Effort"（思考力度）参数，默认是High。这意味着模型会做更深度的推理，反复检查自己的逻辑。
听起来没问题，代价是Token消耗。在Claude CodeI里，如果你没主动调这个参数，模型就会自动进行扩展思考，这会把Token消耗乘以好几倍。Anthropic官方的建议是，对于简单任务，把Effort从High改成Medium，能省不少钱。
简单的Bug修复或代码补全，完全不需要模型深度思考。但你一旦忘了调，就会在不知不觉中多花钱。
智能体群还在实验阶段
Claude Code的新功能"智能体群"听起来很诱人——让多个Claude实例同时工作，一个主Claude指挥其他的分身。但官方特别强调了，这还在实验阶段。
Borris Cherny（Claude Code之父）亲自警告说，这个功能"可能会消耗大量Token"。
真实情况是，多个智能体并行工作时，通讯开销、任务重复、协作冲突都会增加Token消耗。
而且如果任务分解不当，几个智能体可能在做重复的工作，完全是在浪费钱。
代码合并的隐形成本
多个智能体并行开发时，代码冲突是避免不了的。系统用了Git Worktree来隔离工作区，但最终合并还是需要人工审查。
更坏的是，如果其中一个智能体产生了"幻觉"（输出错误或不合逻辑的代码），这个错误会传递给后续的智能体，导致整个团队在错误方向上并行工作。
Token成本会指数级上升。
