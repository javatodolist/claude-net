# OpenClaw小龙虾如何系统性节省Token，有没有可落地的方案？

AI工具导航站
同名“AI工具导航站”，跟上时代的脚步

Token 这个东西，用 OpenClaw 之前你不会在意。
用了以后，你会发现，它就像你家水表，你不盯着它，它就疯跑。
龙虾每干一件事，都在烧钱，读文件，烧，想问题，烧。
确认一遍刚才做的事，再烧一遍。（它是真的费钱。。。。。）
我把我自己用下来总结的方案，分成三层来讲。
第一个：换模型
Claude Opus 4.6，好是好，但真的贵。
你让 Opus 去帮你改一个变量名，这就是用大炮打蚊子，纯粹是在烧钱。。。
怎么分：
简单任务，改格式、加注释、小改动，就用国产的模型。
复杂任务，架构设计、难 bug、需要大量推理的，才上 Opus，虽然我一直觉得这类复杂的问题效果还是没有Claude code好。
还有就是找便宜好用的模型商，我自己使用的是gptsapi的，它不算便宜，只不过API的价格是和官网一样的，比一些有中间商差价的要便宜一点，这种方法的好处就是不需要订阅套餐，用多少就扣多少钱。
除了接入龙虾外，还可以接入Cursor。
方法二：把 CLAUDE.md 瘦下来
很多人的 CLAUDE.md 写的跟论文一样长。
每次对话开始，龙虾都要把这玩意完整读一遍，塞进上下文。
你写了五千字的规范，它就先吃五千字的 Token，一个字没干，先烧了一笔。
你可以吧CLAUDE.md 只留三类内容——你是谁、项目结构在哪、最关键的几条规则。
其他的什么"代码风格要优雅"、"注释要清晰"之类的，全删了，必要的提示词还是需要的。
方法三：上下文别让它无限膨胀
龙虾干活的时候，上下文会一直往里塞东西。
读了文件塞进去，执行了命令塞进去，报了错塞进去，修了错塞进去。
干到一半，上下文已经大得离谱了，后面每一步都在拖着这个巨大的包袱往前走。
几个能落地的动作：
一，任务做完就 /clear。
一个任务完成了，马上清掉上下文，开新的对话做下一个任务。
不要让两个不相关的任务共享同一个上下文，那是最浪费的。
二，用 /compact 压缩历史。
OpenClaw 有这个命令，它会把之前的对话压缩成摘要，替换掉原始内容。
上下文太长的时候，先 /compact 一下，再继续。
三，读文件要精准，别让它读整个文件。
你让龙虾"看一下这个文件"，它会把整个文件塞进上下文。
换成"看第 50 到 80 行"，Token 直接少一大截。
说白了，你问得越准，它烧得越少。
还有几个零散但很管用的小动作：
.openclaw 的 ignore 文件配好，把 node_modules、dist、.git 这些全加进去。
不然龙虾有时候会脑抽，把这些文件也扫一遍，白白烧一堆 Token。
每次给龙虾发指令，说人话，说精确的人话。
"帮我优化一下代码"这种说法，它不知道你想要什么，它就会自己猜，猜的过程就是在烧你的钱。
换成"帮我把 getUserInfo 这个函数的请求改成异步"，它直接干，干完收手。
