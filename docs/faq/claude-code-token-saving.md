首先我们要理解 Claude Code 的运行逻辑：为了保持逻辑连贯，它每次对话都会带上大量的上下文（Context）。
尤其是使用Opus 4.5这种顶级模型时，由于其参数量和推理成本极高，官方配额消耗是 Sonnet 的数倍。
下面是自己我总结的几个方法。
1.严格进行配置
这是最容易被忽视但效果最明显的。Claude Code 会默认扫描目录，如果你的node_modules、dist、build或者大的.git文件夹没屏蔽，它每次检索都会浪费大量 Token。
在项目根目录创建.claudignore，把所有非代码逻辑的静态资源、依赖包全写进去。
2. 修改 settings.json 限制上下文
如果你使用的是集成环境，可以在配置中限制Context Window，
减少“对话历史深度”。默认可能会保存过去 20 轮对话，你可以手动调低到 8-10 轮。这样虽然它会弱一点，但能省下 40% 以上的 Token。
3.任务颗粒度拆解
不要给 Claude Code 下达“帮我重构整个模块”这种模糊指令，明确告诉它“只修改auth.ts中的加密逻辑”。指令越具体，它读取的文件越少，Token 消耗呈几何倍数下降。
还有其他的方法，就是调用便宜的模型，像是deepseek，智谱的模型都可以使用，这样你就不用担心他的花费更多。
还有就是目前很多人使用的中转平台，因为Claude国内的支付方式都不行，而且你调用强度高的话，基本上都要封号，如果你是自建的，可以坚持的时间会多一点。
所以现在很多人会使用中转平台，因为它们的逻辑就是自己订阅Max或Pro用户，然后把额度给中转出来，还有一部分的是使用API，这种大家可以感受出来的。
目前很火的有anyrouter和0011.ai。前者是每天都有免费额度，后者是不仅支持Claude code，还支持OpenAI 的 Codex。
不过，最后还是建议，如果是低强度使用，那使用Pro肯定是够了的，但是高强度的使用，必须得加点马力，使用max吧。这种方法也是最好用的
另外补一个省心的选择，[Code80](https://code.ai80.vip/home) 是把真实订阅账号转成 API 来用，和官方 API 完全兼容，换个 endpoint 就能接进 Claude Code，国内支付也支持，不用自己扛封号风险。重度用户想稳定一点的话可以看看 [code.ai80.vip](https://code.ai80.vip/home)。
