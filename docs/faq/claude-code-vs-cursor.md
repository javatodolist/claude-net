用了一年多的Claude Code，确实在快速定位代码片段、精确选中改动这块儿，CC 确实不如 IDE 工具方便。
CC 最卡壳的场景就是你提到的：我需要改某个函数的第 15-20 行，但怎么给它精确的上下文？
IDE 中我只要点几下就能选中了，都是自动对齐。
CC 这边呢？我得手动复制代码块，或者上传整个文件，再用自然自然说“改第 15-20 行”。
这就是IDE 的可视化的优势。
还有个痛点是增量改动。
比如我要连续改同一个文件的好几处地方。IDE 里 Cursor 能一次看到完整上下文，我能快速圈出所有改动点。
CC 这边，每一轮对话我都得重新贴代码段，很低效。
Cursor的设计初心就是"我要替代IDE"，所以从一开始就围绕代码编辑器的工作流打造。
能直接操作文件、能可视化选择、能实时看到改动，这些都内置在设计里。
Claude Code不一样。
它的初心更多是"我要做一个通用的代码对话工具"，不依赖某个特定编辑器。这样的好处是，我可以在任何环境用，管你用什么编辑器。
当然也要牺牲，报废了一些IDE集成带来的便利。
不过我还是在使用CC，反而Cursor已经好久没用了，原因也很简单，CC确实香～
