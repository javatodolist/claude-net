CLAUDE.md 到底有多强？给大家看几个使用玩法
一、拒绝手写，一
先来看一下最让大家头疼的配置问题。
很多小白一上来就对着空白文档发呆，想手写规则。
大错特错！
最狠的操作是直接在终端敲一个命令：/init
屏幕上瞬间就会开始疯狂刷屏。Claude 会直接扫描你的 package.json，分析目录结构，读取关键文件。
它会自动生成一份“文档”，把你的技术栈、代码风格、依赖关系扒得干干净净。
二、“记忆分层”机制
以前我们用 Cursor 也就是写个 .cursorrules，但在 Claude Code 的体系里，记忆是有等级的！
大神们扒出来的逻辑是这样的：
全局记忆（Global Memory）：这是你的私人偏好。比如“我讨厌写分号”、“永远用 TypeScript”。这一层跟着你的账号走，一人配置，全项目通用。
项目记忆（Project Memory）：这就是根目录下的 CLAUDE.md。团队共享的“圣经”，包含架构图、API 规范。
模块化规则（Modular Rules）：这才是杀手锏！你可以在 .claude/rules/ 目录下创建 testing.md（专门管测试）、security.md（专门管安全）。
Claude 会根据你当前修改的文件，自动调用对应的规则。
这就相当于给你的 AI 员工配了 5 个不同的大脑：有的负责安全，有的负责测试，有的负责前端。
三、“复利工程”
最近看到很多人都在说 GPT 越来越笨，而 Claude 却越来越聪明。
原因找到了！就是因为 Claude Code 支持 “复利工程 (Compounding Engineering)”。
什么意思？
举个例子：你花了一下午，终于排查出一个因 SDK 版本过低导致的离谱 Bug。
在以前，修好就完事了。下次 AI 还会犯同样的错。
但在 Claude Code 里，你只需要对着它说一声：
把这个Bug的起因和解决方案，写进 CLAUDE.md！”
甚至可以用 /memory 命令直接固化下来。
意味着，同一个 Bug，你的团队永远不会遇到第二次。
