# 手机发条消息电脑就开始干活 Anthropic把Claude真正推向了行动型Agent

![Claude Computer Use](/assets/images/localized/api.ibos.cn-cc523f0bdc42.jpg)

## 写在前面
很多人对 AI 编程工具的想象，还停留在“帮我写段代码”“帮我改个 Bug”“帮我解释这段报错”。这当然已经很有用，但它本质上还是一个坐在对话框里的助手：你要在电脑前、你要发指令、你要盯着结果。

Anthropic 这次一口气放出的几个功能，把这个边界往前推了一大截。Claude 不只是会写代码了，它开始能直接动你的电脑、接收你从手机发来的任务、在后台自己安排时间执行事情。换句话说，它开始从“回答你”变成“替你动手”。

最值得关注的，不是某一个功能点本身，而是这几个能力拼在一起之后出现的新工作流：你人在外面，手机上发一句话，Claude 在你的 Mac 上点鼠标、敲键盘、开应用、跑命令、截结果，再把执行反馈回手机。问题一下就变了——这还是聊天机器人吗，还是已经更像一个行动型 Agent？

---

## 最大的变化不是更聪明，而是 Claude 开始真的“会做事”了
来源里提到，Anthropic 同时发布了三件事：Computer Use、`/schedule`、还有 Claude Code Desktop。

如果只把它们当成连续几个新功能看，你很容易低估这次更新的意义。因为真正重要的是，这三者对应的是三个完全不同的能力层：

- **Computer Use**：让 Claude 可以直接操控电脑界面
- **Remote/Dispatch 工作流**：让你可以不坐在电脑前，也能给它派活
- **`/schedule`**：让它把任务挂到固定时间，自己在后台执行

把这三层叠起来，你得到的就不再是一个“会回复消息的模型”，而是一个有执行界面、有远程入口、还有时间调度能力的自动化 Agent。

这才是这篇内容真正值得看的地方。因为过去很多人讨论 AI 编程，还在纠结“补全准不准”“代码风格像不像我”“能不能一次写完需求”。但现在开始拉开差距的，可能不是回答质量本身，而是**谁先把 AI 从前台对话框里放出来，接进真实工作流里**。

---

## Computer Use 到底是什么：Claude 可以直接接管你的 Mac
来源里最炸的一句，是 Anthropic 产品负责人 Felix Rieseberg 的原话：

&gt; 今天，我们发布了一项功能，让 Claude 可以控制你的电脑：鼠标、键盘和屏幕，赋予它使用任何应用程序的能力。

关键不是“可以控制电脑”这几个字，而是后面那句：**任何应用程序**。

这意味着什么？

不是只会操作浏览器，不是只会在终端里跑命令，也不是只能在 Anthropic 自家的界面里点几下按钮。只要一个任务本来就能通过鼠标和键盘完成，理论上 Claude 就能接过来做。

这和过去那类只能调 API、只能走特定工具链的 Agent 很不一样。它不是在受控的狭窄接口里工作，而是开始直接进入你已经在用的桌面环境。PowerPoint、日历、浏览器、图片编辑器，这些人每天点来点去的应用，现在都被纳入了 Claude 的可操作范围。

当然，来源也明确提到，这个能力还处在 Research Preview 阶段，而且 Felix 自己也承认：整个 computer use 领域还很早，Claude 的操作会缓慢而谨慎，远比人类慢。

所以现阶段你不该把它理解成“立刻全面替代人工操作”，而更应该理解成：**AI 已经跨过了只能回答和建议的阶段，开始进入实际执行阶段。**

## 真正让人有画面感的，是“手机发令，电脑干活”
这一轮演示最抓人的，不是模型参数，也不是 benchmark，而是那个非常直观的工作流：人不在电脑前，任务却照样往前推进。

![](/assets/images/localized/api.ibos.cn-58e7198967d6.png)

来源里展示了三个具体场景，而且都不是那种“实验室演示专用任务”，而是你真的能想象自己会用上的事。

### 场景一：导出 PPT 并附到会议邀请里
用户在手机上说：赶着去赴约，帮我把 pitch deck 导出成 PDF，附到下午 2 点的会议邀请里。

Claude 接下来做的事情不是“告诉你怎么操作”，而是直接在电脑上：

- 打开 PowerPoint
- 点菜单导出 PDF
- 切换到日历应用
- 找到下午 2 点的会议
- 把 PDF 附上去

最后还会告诉你，它抓的是今天早上 9:47 编辑的版本，已经全质量导出。

这个场景最有意思的地方在于，它不是单纯的软件自动化，而是接住了一个非常自然的人类表达：你在赶路、来不及、帮我处理一下。Claude 把这句话翻译成了一串桌面操作流程。

### 场景二：启动开发服务器并截图
这个场景对开发者更有感觉。

用户说：启动开发服务器，截个 library 页面的图，下午 3 点的 demo 之前发给我。

Claude 会先调用 Claude Code 跑命令启动服务，再打开浏览器访问 localhost，找到目标页面，然后截图发回。

![](/assets/images/localized/api.ibos.cn-f3a3d31a5281.gif)

![](/assets/images/localized/api.ibos.cn-43934d32d86a.jpg)

这个例子之所以重要，是因为它把两套能力串起来了：

- Claude Code 负责命令行和代码上下文
- Computer Use 负责 GUI 操作和结果获取

也就是说，Anthropic 不是在做一个孤立的“电脑操作”功能，而是在把命令执行能力和桌面操作能力打通。

### 场景三：批量处理 133 张照片
第三个场景则把这套东西从开发扩展到了通用桌面工作流。

用户让 Claude 把桌面上的店铺照片统一处理成 1200px PNG，并在右下角加白色 logo。Claude 打开图片编辑器，加载照片，设置导出参数，最后批量处理完成并反馈：133 张照片已经放到新文件夹里。

![](/assets/images/localized/api.ibos.cn-cf68aab13a48.gif)

![](/assets/images/localized/api.ibos.cn-3c61f6c264f6.jpg)

这里来源还特别强调了一个细节：不是你先写好脚本，然后让它去跑；而是 Claude 直接进入图片编辑器这种现成 GUI 软件里，像人一样完成整套流程。

这说明它开始具备一种很关键的现实能力：**不要求世界为它重写接口，它可以直接进入现有软件生态。**

## 为什么这次比去年更值得看：不是技术概念新了，而是工作流终于闭环了
来源里提到，Computer Use 这个概念 Anthropic 去年就提过，也做过 research preview。当时的问题很明确：慢，而且不稳定。

所以这次真正的看点，不是“它终于快到像人类了”——并没有。真正的看点是，**它和 Dispatch / Remote Control 这种远程入口结合起来后，第一次形成了完整闭环**。

闭环是什么？

- 你在手机上下达任务
- Claude 在你的 Mac 上执行
- 执行完再把结果回推到手机

有网友在来源中说得很准：真正的解锁不在于屏幕控制本身，而在于移动端的上下文和桌面端的执行力之间搭起了桥。

这句话很重要。因为以前很多所谓“AI 自动化”最大的问题，是它要么只能在云端想，碰不到你的本地环境；要么只能在本地跑，但你必须守在电脑前。现在这套组合把“远程发令”和“本地执行”接起来了。

对于开发者来说，这代表的不是一个更酷的 Demo，而是一种新工作模式：

- 你不一定要守着电脑
- 你不一定要在终端里盯每一步
- 你可以把目标交给它，然后等结果回来

这会直接改变很多零碎工作的处理方式。不是所有任务都需要即时互动，有些事情只要明确目标，AI 完全可以异步替你往前推一步。

## 同一天发布的 `/schedule`，把 Claude 又往前推了一层
如果说 Computer Use 是“它能动你的电脑”，那 `/schedule` 解决的就是“它什么时候自己开始动”。

来源里把它叫作“云端龙虾”，这个比喻虽然戏谑，但很传神。因为之前 Claude Code 已经有了 `/loop`，能在本地会话里定期执行任务，但那更像是养在终端里的小东西：终端一关，循环就断了。

`/schedule` 不一样。它跑在 Anthropic 的云基础设施上，电脑关了、网络断了，它还是会照样到点干活。

![](/assets/images/localized/api.ibos.cn-6d3b47dbf198.jpg)

![](/assets/images/localized/api.ibos.cn-9599ece84c3f.png)

来源举的例子也很典型：

```bash
/schedule 每天早上检查昨天合并的所有 PR，
根据变更更新文档，
然后通过 Slack 发到 #docs-update 频道
```

Claude 直接创建一个工作日早上 9 点执行的任务。

这件事单看好像只是“加了个定时器”，但如果你把它和前面的 Computer Use、Remote Control 放到一起来看，味道就完全不同了。

因为现在 Claude 已经同时拥有：

- **时间维度**：它可以自己按时执行
- **环境维度**：它可以碰真实电脑和真实应用
- **入口维度**：你可以远程给它派活
- **工具维度**：它还能接 Claude Code、MCP 和外部服务

这时候它的定位就真的开始偏向“基础设施”了，而不是一个增强版聊天机器人。

## Anthropic 自己的内部用例，其实已经把方向说透了
来源里提到，Anthropic 工程师 Noah Zweben 分享了一个内部使用案例：他们有一个定时 Claude 任务，在全自动维护一个 Go 版 twin library，对应正在开发的 Python 库。

这句话特别值得反复看。

因为它说明 Anthropic 自己已经不只是把 Claude 当成“写几个函数的协助工具”，而是在让它持续维护一整条工程资产。Python 那边 API 变了，Claude 会自动检测，再把 Go 版本同步跟上。

这已经不是“辅助写代码”了，而是一种长期托管的工程维护角色。

再往前一步想，如果把这种能力和 Computer Use 叠起来会怎样？来源中的一句评论给了答案：你会得到一个能跑定时任务的后台 worker，而且还能操控任何应用。

对开发者来说，这个想象空间很大：

- 定时检查构建状态
- 自动同步文档
- 例行巡检依赖和漏洞
- 生成日报并发 Slack
- 在需要 GUI 的应用里执行固定动作

以前很多事不是做不到，而是自动化链路断在了某个环节：要么不会点 GUI，要么不能后台运行，要么只能本地盯着。现在这些断点在被一块块补齐。

## 这轮高频更新，透露的不是“发版勤快”，而是产品方向已经很清楚了
来源还盘了一遍 Anthropic 近几个月的更新节奏：模型升级、Office 集成、Remote Control、Memory、Marketplace、Code Review、1M 上下文、Channels，再到今天的 Computer Use 和 `/schedule`。

你把这些点连起来看，会发现它们并不是随机散落的功能，而是在沿着一条非常一致的路线往前走：

### 第一阶段：会说话
早期 Claude 更像一个强大的对话模型。你输入，它输出。

### 第二阶段：会写代码、会调用工具
Claude Code、MCP 这些能力，让它开始进入工程上下文，不只是说，还能查文件、跑命令、连外部系统。

### 第三阶段：会被远程调度、会接收事件
Remote Control 和 Channels 让它不再局限在“你坐在这台电脑前”的同步交互里。

### 第四阶段：会动电脑、会自己排班
Computer Use 让它可以碰真实桌面环境，`/schedule` 让它可以在时间维度上自主执行任务。

所以问题已经不是“Claude 会不会越来越像 Agent”，而是它已经在变成 Agent，而且速度比很多人预期得快得多。

半个月十几个功能，这不是小修小补，而是在快速补全一整套行动系统。

这也是为什么 Anthropic 这一轮更新会让人明显感觉到“味道变了”。以前大家讨论 Claude，重点还在模型表现；现在更值得关注的是它在真实工作流里的可操作性。

## 常见问题

### Q1：Computer Use 现在已经成熟到能日常重度依赖了吗？
A：还没有。来源里已经明确说明它仍处于 Research Preview，Anthropic 自己也承认这类操作会比较慢、比较谨慎。所以现在更适合把它理解成“已经能跑通关键闭环”，而不是“所有桌面操作都能立刻无脑托管”。

### Q2：这次最该关注的是 Computer Use 还是 `/schedule`？
A：单看惊艳程度，当然是 Computer Use；但如果从长期工作流价值看，真正值得一起看的其实是两者叠加。一个负责行动能力，一个负责时间调度，组合起来才更接近可持续运行的 Agent。

A：因为它把移动端上下文和桌面端执行力接通了。你不必守在电脑前，也不必把所有任务压缩在同步会话里完成。很多重复工作会因此自然转成异步处理。

### Q4：对开发者最现实的价值体现在哪？
