先说结论，Claude code确实非常好用，可以说是目前最好用的AI编程工具，但是它这个话可能说过头了。
一个小时生成一个可用且是谷歌这么大的公司的项目，多多少少是有点夸张了。
我经常在Hacker News看，大家基本都同意一个结论：Claude Code通常只能搞定70-80%的任务，剩下的得人来。
有个开发者分享了个典型案例：三个月没动的代码库重构项目，几十个文件、改数据库、换API端点、加完整测试——扔给Claude Code晚上11点跑，早上7点出活，测试全过。
有经验的人都是这么用的：存个检查点，让Claude跑半小时，然后决定接受还是重新来。
因为有时候重新开始比修改AI的瞎改更快。甚至有团队一次跑多个Claude实例，然后挑最好的方案，听起来像在赌概率。
Claude最拿手的是「问题明确、流程标准、能快速验证」这一类活。
新闻通讯自动化、这种事能给产品经理每周省5到10小时。
但开创性的活、架构决策、需要深度业务理解的优化，Claude这块就不行。
海外开发者一直在强调，他们信Claude的执行，但不会把设计权交给它。
人类写的代码值得信任，因为人能解释想法，出错时能质疑假设，AI不同，它优化的是顺应人的偏好而不是正确性本身。
「一小时搞定一年活」这句话，准确说应该是「高度重复、标准化、容易验证的工作上，Claude能显著压缩执行时间」。这已经挺强。
但要把它当成AI的万能钥匙，结果就是在实际干活时频频失望。海外开发者社区的共识很清楚：Claude是效率倍增器，不是效率替代器。
目前过内的程序员，大概有三种方法使用Claude code
方案1：拦截请求方案
拦截请求方案是去魔改Claude Code发送请求的api，替换成Gemini等其他模型api，目前开源社区有3个实现 1. anthropic-proxy 2. claude-code-router 3. claude-bridge
这个方案的好处是便宜稳定，但是效果很一般，凑合体验下，毕竟适配最好的是Claude模型。
方案2：Claude 网页版逆向API
逆向API 是指通过程序去逆向 Claude 网页版的api，利用账号池形成API方案，再配合方案1，成本比官方API低30%左右，但在Claude Code应用不如官方效果好，有点不稳定。
方案3：Claude Max 账号池
方案3是最近有大牛搞出来的新技术方案，简单来说，就是利用 Claude Max 200刀 的账号池 + Claude Code 原生API，
通过代理和负载均衡形成的一套技术方案，价格能做到比Claude Max 100刀订阅价低60%，很屌。
目前很多Claude code都是使用的第三种方法，所以我们使用它会比官网的要价格要低很多。
比如我现在使用的0011，它的使用逻辑就是购买了它的会员，它会给你一个API，然后使用这个API在Claude code进行配置，同时也可以在vs code中使用。
而要说为什么会选择0011.
就是不知道这个平台用了什么技术，它给的API不仅可以使用Claude code，还能使用Codex，刚好满足我的需求。因为我自己使用这些工具，会用两个进行交叉验证，这样效率会高很多。
