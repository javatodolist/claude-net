# 还在切 tmux 和一堆终端标签 Claude Code 这次把多 Agent 协作塞进了一个界面

![Banner](/assets/images/localized/dev.ua-881b8fbeb89c.jpg)

## 写在前面

如果你已经开始把 Claude Code 当成真正的开发搭子来用，一个很快就会撞上的问题不是“它会不会写”，而是“我同时开了 3 个、5 个、8 个 agent 之后，还管不管得住”。

终端标签页越开越多，tmux 窗格越切越乱，哪个任务卡住了、哪个任务跑完了、哪个任务在等你拍板，最后都得靠你自己记。AI 真开始接活之后，新的瓶颈反而变成了**人怎么管理一群 AI**。

Anthropic 这次放出的 Agent View，解决的就是这个问题。它不是再加一个会写代码的功能，而是给 Claude Code 补上了多 agent 并行时代最缺的那块控制面板。

---

## 现在真正麻烦的，不是让 AI 干活，而是别让多任务现场失控

很多开发者已经不满足于一次只跑一个任务了。

一个 agent 在改接口，一个 agent 在跑测试，一个 agent 在整理 PR，一个 agent 在盯长时间任务，这种工作方式已经越来越常见。问题在于，终端天然不是为这种密集并行调度设计的。标签页一多，管理成本会迅速反噬效率。

Agent View 的核心思路很直接：**把分散在不同会话里的 agent，收回到一个统一界面里看管。**

这样做的价值不只是“看起来整洁”，而是把多任务开发从一种高手靠经验硬撑的状态，变成普通开发者也能稳定驾驭的日常工作流。

---

## Agent View 到底做了什么：把所有 Claude Code 会话放进同一张总览里

Agent View 是 Claude Code 的单一界面，用来同时启动和控制多个 AI agent 会话。

它解决的是过去那种很典型的混乱场景：

- 终端里开着多个标签页
- tmux 配置越来越复杂
- 每个会话各干各的，你得自己记进度
- 只有切进去看，才知道哪个任务在等你

现在这些信息会被集中到一个列表里。你能直接看到所有活跃任务的状态，包括：

- 当前进度
- 最近一次交互时间
- 哪些地方需要人工介入

这点很关键。因为当 AI 任务开始并行以后，最浪费人的不是敲命令，而是**上下文切换**。你不停来回看不同终端，本质上是在给“管理 AI”付认知税。Agent View 做的事，就是把这笔税往下砍。

---

## 它怎么进入工作流：左方向键，或者 `claude agents`

这个新模式的入口并不复杂。

你可以直接按左方向键进入，也可以输入 `claude agents` 打开。进入之后，Claude Code 会把当前的多会话状态整理成一个可浏览、可切换、可干预的统一视图。

比起过去那种“记住每个终端窗口里跑了什么”，现在更像是你终于有了一个任务总控台。

对于已经习惯在 CLI 里工作的开发者来说，这个设计很聪明。它没有强行把 Claude Code 改造成一个脱离终端的新产品，而是在原来的命令行体验上补了一层管理能力。你原来怎么干活，现在还是怎么干活，只是多 agent 并行这件事终于没那么乱了。

---

## 真正有用的是后台能力：`/bg` 和 `--bg` 让 agent 不必占着你的前台

Agent View 之所以值得看，不只是因为“能看见很多会话”，而是因为它和后台执行能力绑在了一起。

现在任意会话都可以通过 `/bg` 放到后台运行。除此之外，你在发起新任务时也能直接用 `--bg` 参数，把任务从一开始就丢到后台。

这意味着什么？

意思是你终于不用围着一个 agent 干等。Claude 在后台继续推进任务，只有在需要你给明确选择、补充上下文或者做决策时，你再回来处理。

这种模式特别适合几类场景：

- 长时间代码生成或重构
- 大批量测试与检查
- 持续监控 PR 状态
- 自动更新报表或仪表盘

说白了，Agent View 不是单纯把“多个 AI”展示出来，而是把它们组织成**可以被调度的工作队列**。

---

## 多 Agent 最像样的用法，已经不只是“同时开几个窗口”了

这个功能最有意思的地方，在于它明确给出了多 agent 开发的实际用法。

一个典型场景是：你把多个想法或任务一次性交给不同 agent，每个 agent 还可以绑定对应 skill，各自并行推进。等你回来时，看到的不是一堆散乱会话，而是一串已经准备好给你 review 的结果，比如一组待审 PR。

另一个场景是长期运行任务。比如：

- 盯住 pull request 的变化
- 自动同步某些状态信息
- 定期刷新 dashboard
- 持续等待外部条件满足后再往下执行

这些任务以前也不是不能做，但往往需要你自己搭一堆终端管理方式，甚至手动维护 tmux。现在 Anthropic 明显是在把这种“进阶玩家玩法”产品化、默认化。

这件事的信号很清楚：**Claude Code 已经不再假设你一次只和一个 agent 对话，它开始默认你会同时运营一个 AI 小团队。**

## Claude Code 到底是什么？为什么 Agent View 会这么重要

如果你之前还没系统用过 Claude Code，可以把它理解成 Anthropic 面向开发工作流做的命令行 Agent。

它和传统代码补全工具最大的区别，不是补全能力更强，而是它本来就不是只负责“补几行”，而是能围绕一个任务持续往前推。常见能力包括：

- 读取和理解项目文件
- 修改代码、跨文件重构
- 执行命令、跑测试、查看报错
- 处理 Git 工作流
- 借助技能和工具把复杂任务拆开执行

Agent View 重要就重要在，它补齐了 Claude Code 从“单兵 agent”走向“多 agent 协作”的那一环。

以前的瓶颈是模型能力，现在越来越像是**任务编排能力**。谁能把多个 agent 稳定组织起来，谁就更接近真正可落地的 AI 开发工作流。

## 这次更新背后的真正变化：Claude Code 开始从“单线程助手”变成“可管理的并行系统”

很多人第一次接触 AI 编程工具时，关注点都在模型是不是更聪明、写代码是不是更快。

但工具走到这一步，新的分水岭已经出现了：当一个开发者手里同时跑着多个 AI 会话时，系统能不能把这些会话组织起来、追踪起来、按优先级接回来。

Agent View 给出的答案很务实。它没有试图炫更玄乎的概念，而是先把最真实的痛点做掉：

- 别让我在一堆标签页里找任务
- 别让我自己记哪个 agent 卡住了
- 别让我为了并行协作去维护复杂 tmux 配置
- 别让我必须一直盯着前台等 AI 跑完

这类能力看着不如新模型参数那样热闹，但对真实开发效率的影响，往往更大。

因为从一个 agent 到多个 agent，变化的从来不只是数量，而是整个工作方式。你不再只是“问一个 AI 问题”，而是在调度一组会持续产出结果的执行体。

## 常见问题

**Q: Agent View 最直接解决的是什么问题？**

A: 解决多会话管理混乱。过去同时开多个 Claude Code 任务时，你得在不同终端标签和 tmux pane 之间来回切。现在可以在一个列表里统一看状态、进度、最近交互时间，以及是否需要你介入。

---

**Q: 它和单纯多开几个终端窗口有什么本质区别？**

A: 区别在于“可管理”。多开窗口只是把任务摊开，Agent View 则是把这些会话变成可观察、可切换、可后台运行的一组任务系统。

---

**Q: `/bg` 和 `--bg` 有什么用？**

A: `/bg` 可以把现有会话放到后台继续跑，`--bg` 则是在创建任务时就直接后台启动。这样你不用一直盯着前台，只在 Claude 需要你给决定或补信息时再回来处理。

---

**Q: 这个功能适合哪些任务？**

A: 特别适合长时间运行任务，比如大规模改代码、持续测试、监控 PR、自动更新 dashboard，或者同时推进几条独立思路并最后集中 review。

---

**Q: 现在谁能用上 Agent View？**

A: 目前它以 Research Preview 形式开放给 Pro、Max、Team、Enterprise 计划用户，也能通过 Claude API 使用。

---

**Q: 国内用户如果想更方便地接入 Claude Code 怎么办？**

A: 如果你更习惯 API 方式接工作流，国内用户可以通过 [Code80](https://code.ai80.vip/home) 更方便地使用。
